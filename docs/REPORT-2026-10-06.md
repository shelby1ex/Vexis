## 2. Sidebar "boxes" bug fixed

**Root cause:** `vendor/vertex/css/vertex.css:1037,1058` restates
`.modal-overlay` / `.settings-modal-overlay` as `display:flex`, overriding
`style.css`'s `display:none` (styles load order: style → vertex → styles).
JS only toggles `.open`, so overlays rendered as boxes on open.

**Fix:** `vexis_ui/styles.css:3` —

```css
.modal-overlay:not(.open),
.settings-modal-overlay:not(.open) { display: none; }
```

Also: global `button { border:none; background:transparent; color:inherit; }`
(UA 3D borders were the sidebar row boxes — rows are `<button class="chat-item">`)
plus `.chat-item`/`.chat-item-del` hover-reveal delete-icon styles.

## 4. Latency investigation ("30 seconds thinking")

Measured directly against the engine (session → `prompt_async` → message poll):

| model | first text | turn complete |
|---|---|---|
| `mimo-v2.6-flash-free` | ~7.2s | ~5–6s |
| `muse-spark-1.3-contributor-free` | ~0.7–0.8s* | ~3s |

\* verified with a marker prompt: real first text ≈ 7s worst case, and log shows
turns completing in 3–6s. **The engine was never the 30s problem.**

Real causes found and fixed:

1. **Engine cold boot ≈ 22s** — first messages launched before the engine
   listened failed or hung. Fixed in `app_desktop.py:main()`: waits up to 40s
   for an already-booting engine (started by `run.bat`) before spawning a
   duplicate, then up to 60s after spawning. No more double-engine launches.
2. **UI silence** — old first poll waited 1s and painted only on SSE deltas;
   users stared at a static screen. Fixed: 250ms first poll + thinking
   animation + typewriter (see §3).
3. Occasional provider `stream error`s exist in the engine log (free hosted
   models) — the UI's retry/model-switch hint card already handles those.

Note: 3 stale `opencode` processes from the morning (10:25, 13:36, 16:49) were
still running — restart opencode after this session to free RAM and load the
new permission config on those instances.
